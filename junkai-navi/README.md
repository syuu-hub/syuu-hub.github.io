# 巡回ナビ（エンドレス需要巡回ナビ）

目的地を設定せず、需要エリアを回り続けるスマホ用ナビです。Googleマップは使っておらず、無料のオープンデータとオープンソースだけで動きます。
iPhone・Androidのブラウザで開き、「ホーム画面に追加」すればアプリとして使えます（PWA）。

## 特長
- Googleマップ風のナビ画面：上部の右左折バナー（「その先」表示付き）、ヘディングアップの3D地図、下部の操作パネル（速度は表示しません）
- 日本語の音声案内（「およそ300メートル先、右折です」「まもなく左折です。その先すぐ右折です」）
- **急な指示変更をしない仕様**
  - 確定区間：今から30秒以内（最低300m）に通る道は、需要が変わっても変更しません
  - 一度案内した右左折は必ずそのまま
  - 新しいルートは確定区間の終点から、進行方向を保ったまま接続します
  - 接続直後すぐに右左折が必要な候補は使いません
  - 需要が1.3倍以上良くなった場合だけ、3分以上の間隔をあけて切り替えます
  - 右折・Uターン・短い間隔での連続右左折・直近20分に走った道を避けるよう候補を評価します
- 需要エリアの入力方法を選べます（設定 → 需要エリアの入力方法）
  - **任意で設定**：周辺の駅・ホテル・病院・繁華街・商業施設を自動で取り込み（OpenStreetMap）、自分の得意な地点も追加できます
- 登録地点（設定 → 登録地点の一覧を開く）
  - **住所から追加**：住所（または施設名）を入力すると位置を調べて登録します（国土地理院の住所検索、見つからなければ OpenStreetMap）。地図の長押しでも追加できます
  - 一覧で編集・削除。イベント（催し物）は使いません（始まる時は駅などから歩いて来るので、終わった後も含め需要に入れない）
  - 常設の地点には **需要がある時間帯・曜日** を指定できます（例 22時〜2時・金土）。指定した時間帯・曜日だけ需要を高く見ます。指定しなければ一日中同じ（営業ログから登録した地点は乗車の傾向から自動）
  - **CSVで読み込み・保存**：列は「名前, 住所, 緯度, 経度, 乗車回数, 時間帯（例 7-10, 18-24）, 曜日（例 平日、土日、月水金）」。以前の形式のCSVでも、種類が「イベント」の行は使いません。名前と住所だけのCSVも読み込め、緯度・経度が空なら住所から調べます。同じ名前・住所の地点は上書きします
  - **タクシーアナライザの営業ログCSVも読み込めます**：乗車した場所（施設名・住所）ごとにまとめて登録し、乗車が多い場所ほど需要を高く見ます（1回=1倍〜上限3倍）。**乗車した時刻・曜日の傾向**も場所ごとに覚え、今の時間・曜日に乗車が多い場所ほど高く見ます（前後1時間も半分数え、曜日は平日／土日の傾向も合わせて見ます。乗車回数が少ないうちは傾向を弱めます）。「タクシーアナライザの乗車で使う種類」の設定に従い、初期は乗り場を除きます。読み込み直すと、前回営業ログから登録した場所のうち対象外になったものは消えます
  - 調べた位置は端末に覚えておき、同じ場所は2回目から調べません。施設名だけの場所は、他の地点の近く（60km以内）に絞って探します
  - 登録した地点はこの端末の中に保存されます
  - **タクシーアナライザのCSV**：タクシーアナライザの「出力・設定 → CSV出力 → 営業ログ（全期間）」で保存したCSVを読み込み、乗車した場所と時刻から、今の時間帯に乗車が多いエリアを需要エリアにします。施設・手入力で記録した乗車（緯度・経度が空）は、施設名・住所から位置を調べて使います。「タクシーアナライザの乗車で使う種類」で流し・乗り場・アプリ配車（無線・予約を含む）を選べます。初期は流しだけ（乗り場は待てば乗れる場所なので巡回先から外し、アプリ配車等は呼ばれた場所なので外します）
- **記録はしない**：乗車の記録はタクシーアナライザで行い、このアプリは記録したデータ（営業ログCSV・登録地点）と公開データに基づいて案内するだけです
- **同じ所をぐるぐる回らない**：通ったエリアと、その500m以内は一定時間（初期60分）行き先にしません。ツアーに入っていなくても、近く（250m以内）を通ったエリアは通ったものとして扱います。最近45分に走った道を4割以上通るルートは、他に案があれば使いません。行き先が他に無い時だけ、一番前に通ったエリアへ向かいます
- **ゴールのないエンドレスナビ**：目的地は作りません。ルートの先が2.5km（または3分）より短くなる前に、今のルートの終わりから次のポイントを計算して後ろにつなぎ続けるので、ルートは途切れず、走る先の道が変わることもありません。画面には到着時刻や残り距離ではなく「次に通るポイント」と、そこまでの距離を出します
- **現在地の印はルートの線の上**：ルートの上を走っている間は、GPSの位置ではなくルート上の位置に印を出し、向きもルートの向きにします（GPSの誤差で印が道の横や線の外にずれない）。次の位置が来るまでの間は、地図の動きと同じ速さで線に沿って印を動かします。ルートから外れた時・休止中はGPSの位置です
- 需要マップ：オレンジ一色のヒートマップで、需要が多いほど濃く表示します
- **行き先は最短距離（初期設定）**：需要のあるエリア（一番高いエリアの4分の1以上）のうち、今いる所から道のりで一番近いエリアへ向かいます。道のりはルートサーバーの距離の行列（sources_to_targets）で直線で近い6か所を測り直します（使えない時は直線）。後ろのエリアはUターン・回り込みが要るので遠い扱い。走っている位置に合わせて、今の行き先より3割以上近い需要エリアが出てきたら切り替えます（切替の最小間隔・確定区間のルールはそのまま）。需要のあるエリアを回り切ったら、需要の小さい、まだ回っていないエリアへ。設定で「需要の高さ優先」（需要が高ければ少し遠くても選ぶ）にもできます
- **ルートの見やすさ**：次のポイントまでの区間は濃い青で太く上に、その先の区間は細く淡い線で下に描き、どの線にも進む向きの矢印を付けます。次の右左折（600m以内）には白い矢印を出すので、同じ交差点を2回通るルートでも、今どちらへ曲がるかがわかります。先へつなぐ区間は、これから走る予定の道と4割以上重なるルートを避けます
- **表示エリアをたためる**：巡回中の下の表示は、下にスワイプすると1行にたためます。上にスワイプするか、上の取っ手をタップすると開きます（状態は保存）
- **複数の需要エリアを通り抜けるルート**：候補のエリアが近くに複数あるときは、1か所に向かうのではなく、近い順に2〜3か所を通り抜けるルートにします（1つ先まで2.5km以内・全体で8km以内、2か所目以降は1か所目の3割以上の需要があるエリアだけ）。通過したエリアは読み上げて「回った」扱いにし、次のエリアへ案内します。ルートサーバーには止まらずに通る地点（through）として渡します。通るエリアの数は設定で1〜4（初期値3、1なら従来どおり1か所ずつ）。複数の候補地を通るのが基本で、通常の条件で1か所しか選べない時は、条件をゆるめて（1つ先まで4km・需要1割以上）2か所目を選びます
- 需要の計算（1分ごとに更新し、平滑化して急変を防ぎます）
  - 時間帯と曜日：駅、ホテル、病院、繁華街、商業施設ごとの時間帯の傾向
  - 天気：雨や大雪のときは需要を上げます（Open-Meteoから自動取得、または手動設定）
  - 鉄道：遅延や運転見合わせが起きたら駅の需要を上げます（手動。ODPTのキーを入れれば自動）
- シミュレーション走行：家の中でも動作を確認できます

## スマホで使えるようにする（GitHub Pagesで無料公開）
GPSを使うので **https で公開する必要があります**。
1. GitHubで新しいリポジトリを作り、このフォルダの中身をすべてアップロードします（`test/` と `server/` は無くても動きます）
2. Settings → Pages → Branch を `main`（`/root`）にして保存します
3. 数分後に表示される `https://ユーザー名.github.io/リポジトリ名/` をスマホで開きます
4. ホーム画面に追加します
   - iPhone：Safariの共有ボタン →「ホーム画面に追加」
   - Android：Chromeのメニュー →「ホーム画面に追加」（または「アプリをインストール」）

Cloudflare Pages や Netlify でも同じように無料で公開できます。

## 使い方
1. 「巡回を開始」を押し、位置情報の利用を許可します。初回は周辺の需要スポットを自動で取得します
2. 案内に従って走ります。目的地に着く前に、次の需要エリアへのルートが自動でつながります
3. お客様を乗せている間は「休止」を押すと案内が止まります。降ろしたら「再開」を押すと、今いる所から巡回を再開します（このアプリは乗車を記録しません。乗車の記録はタクシーアナライザで行います）
4. 「需要マップ」で需要の分布を表示できます
5. 地図を長押しすると、自分の得意な地点を追加できます

## 本格運用：自前のルートサーバー
初期設定では FOSSGIS の公開 Valhalla サーバー（無料・毎秒1回まで・稼働保証なし）を使います。個人での試用には十分ですが、複数台で使う場合や業務で使う場合は、自前のサーバーを立ててください。
1. Dockerが入ったPCで `server/` に移動し、`docker compose up -d` を実行します（初期設定は関東。全国にする場合はファイル内のURLを変更）
2. スマホからアクセスするには https が必要です。Cloudflare Tunnel（無料）などで `https://〜` のURLを用意します
3. アプリの「設定 → 詳細 → ルートサーバーURL」にそのURLを入力します

## 調整できる項目（設定画面）
| 項目 | 初期値 | 内容 |
|---|---|---|
| 確定区間 | 30秒 | この時間内に通る道は変更しない |
| 切替の最小間隔 | 3分 | 需要の変化で行き先を変える頻度の上限 |
| 切替に必要な需要の差 | 1.3倍 | これ未満の差では行き先を変えない |
| 営業エリア半径 | 6km | 開始地点からこの範囲内の需要エリアだけを巡回 |
| 行き先の選び方 | 最短距離 | 最短距離／需要の高さ優先 |
| 1回のルートで通る需要エリアの数 | 3 | 近くの需要エリアを順に通り抜ける。1なら1か所ずつ |
| 一度通ったエリアに、また向かうまでの時間 | 60分 | 通ったエリアとその500m以内は、この時間は行き先にしない |

需要の時間帯の傾向や重みは `js/demand.js` の冒頭で変更できます。

## 実際の営業で効くように
- **タクシーアナライザの乗車実績の見方**（営業ログCSV）
  - 乗車が多い場所を基本にし、**時刻の傾向は、その場所（約450m四方）で何度も乗せているほど強く使います**（1回だけの場所は時刻にあまり左右されず、8回で半分、20回以上でほぼ時刻どおり）。時刻は1時間ごとではなく分単位でなめらかに見ます（前後60分で6割）
  - 実際の営業ログ（流し33件・全乗車213件）で「他の日の乗車から、その日に乗せた場所を当てる」検証をすると、以前の1時間ごとの強い重み付けより当たりやすくなりました（流しで、実際に乗せた場所に付く確率が約1.7倍）
  - 平日／休日は **祝日・振替休日・年末年始も休日** として見ます（登録地点の時間帯・曜日、駅や病院などの傾向も同じ）
  - 隣のエリアにも乗車がある所（乗車が続けて見つかる面）を少し高く見ます。エリアの区切りをまたいだだけで需要が分かれて低く見えないように
- **需要は着くころの時刻で見る**：エリアまで数分かかるので、5分先の需要で行き先を選びます
- **GPSの乱れで再検索しない**：精度が60mより悪い位置（ビル街・トンネル）はルートから外れた判定に使わず、再検索は20秒以上あけます
- **ルートサーバーが一時的に使えない時**：行き先を外さず、待つ時間を5秒→10秒→…最大60秒と延ばし、お知らせも繰り返しません。つながったら案内を再開します

## 対象地域：関西圏
- 地図データ（タイル）は関西圏（大阪・京都・兵庫・奈良・滋賀・和歌山）の範囲だけを読み込みます。地図のスタイルを読み込む時に、タイルの出どころに範囲を付けるので、範囲の外のタイルは通信しません
- 地図は関西圏の外へは動かせず、日本全体のような引いた地図（ズーム8未満）も読み込みません
- 住所・施設名の検索も、関西圏の結果だけを使います
- 現在地が関西圏の外の時はお知らせします。範囲は `js/region.js` で変更できます

## 電池の節約
- 地図は、止まっている・ほとんど動いていない時は動かさず（描き直さない）、動く時も次の位置が来る前に終わる短いアニメーションにして、その間は地図を休ませます
- 高解像度の画面でも、地図を描く細かさは2倍まで（省電力モードは1.5倍）
- ルートの線・曲がり矢印は、見た目が変わる時（20m・10m進んだ時、ルートや通るポイントが変わった時）だけ描き直します
- 脈打つ印は、影ではなく拡大と透明度だけで動かします（毎フレームの描き直しをしない）
- 画面が見えていない間は地図を描きません（案内と音声は続けます）
- **省電力モード**（設定 → 案内）：地図を平面（2D）にし、描く細かさとアニメーションをさらに減らし、印も脈打たせません

## 制約・注意
- ブラウザアプリのため、画面を消したり別のアプリに切り替えたりすると案内が止まります。走行中は画面をつけたままにしてください（画面が自動で消えないよう設定しています）
- 渋滞情報はありません。OSMの一方通行や右左折禁止のデータは、市販の地図データより抜けがあることがあります。案内より実際の標識と交通規則を優先してください
- 需要は公開データと、タクシーアナライザの営業ログ・登録地点から推定したものです。タクシーアナライザの記録が増えるほど、自分の営業エリアに合った精度になります
- Open-Meteoの天気は、商用利用の場合は有料プランが必要です。気になる場合は天気を手動設定にしてください
- 地図とデータ：© OpenStreetMap contributors（ODbL）、OpenFreeMap、OpenMapTiles

## ファイル構成
- `index.html`, `css/app.css`：画面
- `js/main.js`：地図表示、GPS、音声、操作
- `js/navcore.js`：確定区間、ルート接続、案内のロック、候補の評価
- `js/demand.js`：需要エンジン
- `js/valhalla.js`：ルートサーバーとの通信
- `js/sources.js`：OSM（Overpass）、天気、鉄道運行情報
- `js/csv.js`：タクシーアナライザの営業ログCSVの読み込み
- `js/places.js`：登録地点（住所からの位置検索、CSVの書き出し・読み込み）
- `js/profile.js`：登録地点の時間帯・曜日（営業ログの傾向、自分で指定）
- `js/calendar.js`：祝日・休日の判定
- `js/region.js`：対象地域（関西圏）の範囲、地図データを範囲内だけにするスタイルの書き換え
- `js/geo.js`：地理計算
- `sw.js`, `manifest.webmanifest`, `icons/`：PWA
- `test/navcore.test.mjs`：走行シミュレーションによる検証（`node test/navcore.test.mjs`）
- `test/csv.test.mjs`：CSV読み込みと需要計算の検証（`TZ=Asia/Tokyo node test/csv.test.mjs`）
- `test/places.test.mjs`：登録地点の住所検索とCSVの検証（`REAL_CSV=営業ログ.csv` を付けると実データでも確認）
- `test/region.test.mjs`：地図データ・住所検索を関西圏だけにする処理の検証
- `test/demand.test.mjs`：現在地の印をルートに合わせる処理・祝日・乗車実績の重み付けの検証（`TZ=Asia/Tokyo node test/demand.test.mjs`）
- `test/profile.test.mjs`：時間帯・曜日の傾向と需要の検証（`TZ=Asia/Tokyo node test/profile.test.mjs`）
- `server/docker-compose.yml`：自前のValhallaサーバー
